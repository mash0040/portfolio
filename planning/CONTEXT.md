# Planning Context

This workspace is for planning the portfolio web app before writing code.

## Purpose
Use this folder for specs, architecture notes, feature ideas, and decisions. The goal is to keep the project focused and avoid building random features without a clear reason.

## App Goal
Create a professional portfolio web app that helps me apply for Entry-Level / Junior Software Developer roles.

The portfolio should show:
- Projects I have built
- Technologies I can use
- My problem-solving process
- My ability to write clean, responsive UI
- My ability to explain technical work clearly
- My resume and contact information

## Target Audience
- Recruiters
- Hiring managers
- Junior developer interviewers
- Technical reviewers
- Potential freelance or volunteer clients

## MVP Pages
- Home
- About
- Projects
- Project Details / Case Study
- Contact

## MVP Features
- Responsive layout
- Navigation
- Project cards
- Project case study pages
- Skills section
- Resume download link
- Contact links
- Cloudflare Pages deployment

## Future Features
Only add these after the MVP is deployed:
- Blog/dev notes
- GitHub API integration
- Project filtering
- Dark mode
- Admin dashboard
- CMS
- Contact form backend
- Animations

## Architecture Principles
- Keep the app simple.
- Use local data files before adding a backend.
- Reuse components.
- Keep content separate from UI when possible.
- Make every page mobile-friendly.
- Avoid adding tools just to look advanced.

## What Good Planning Looks Like
A good spec should answer:
- What are we building?
- Why does it matter?
- Who is it for?
- What content does it need?
- What components are required?
- What is out of scope?
