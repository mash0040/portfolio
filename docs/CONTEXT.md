# Documentation Context

This workspace contains documentation for the portfolio project.

## Purpose
Use this folder to document how the portfolio works, how it is deployed, and how project case studies should be written.

## Audiences
There are two main audiences:
1. Me, as the developer maintaining the project
2. Recruiters or hiring managers reviewing my work

## Documentation Types
- Guides: How something works or how to update it
- Changelog: What changed over time
- Case study templates: Structure for writing strong project descriptions

## Documentation Standards
Docs should be:
- Clear
- Short
- Practical
- Easy to update
- Written in plain language

## Important Docs
- Project case study template
- Deployment guide
- Changelog
- README content ideas

## Case Study Structure
Each project case study should include:
- Overview
- Problem
- Goals
- Features
- Tech stack
- My role
- Challenges
- Solutions
- What I learned
- Screenshots
- Live demo
- GitHub repo

## What Good Documentation Looks Like
Good documentation explains not only what was built, but why decisions were made.
